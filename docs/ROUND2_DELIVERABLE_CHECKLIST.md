# Inkloom AI Round 2 — Build checklist

Use this as a checklist, not as proof that a task has been completed.

## Functional product
- [ ] Creator can create/edit/import a draft, run checks, act on findings and submit.
- [ ] Findings cite approved sources and uncertainty is shown honestly.
- [ ] Reviewer can comment, approve or request changes.
- [ ] Revision history and recurring-issue insights are demonstrable.
- [ ] Admin can edit the source library and manage approved visual assets.
- [ ] Run the functional test plan and record real pass/fail outcomes.

## Research validation
- [ ] Collect 20–40 relevant survey responses if feasible; current baseline in the team's chat was 2 responses on 24 October 2026, not a representative sample.
- [ ] Conduct 3–5 short interviews with creators/reviewers/small-business or marketing users if feasible.
- [ ] Keep an anonymised log: participant type, current review process, time spent, common errors, feedback style, AI concerns, and features valued.
- [ ] Review 3–5 public brand guidelines/content examples and record concrete observations with URLs.
- [ ] Prepare a small labelled set with compliant examples and seeded issues: banned term, incorrect terminology, unsupported claim, outdated fact, long sentence, and exact/near/unapproved image.
- [ ] Measure true positives/false warnings against the labelled set. Do not invent accuracy or time-saving percentages.
- [ ] Compare survey/interview evidence with feature choices and list what changed as a result.

## Submission integrity
- [ ] Provide a judge-accessible repository or clear local demo instructions.
- [ ] Disclose frameworks, libraries, AI assistance and any external model/API actually used.
- [ ] Report actual individual contributions and meaningful commit history.
- [ ] State known limitations, privacy boundaries and future roadmap.
- [ ] Never describe a planned interview, feature, test or deployment as completed unless it is completed.
